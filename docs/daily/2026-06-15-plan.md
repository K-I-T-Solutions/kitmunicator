# Plan – 2026-06-15: Presence ↔ Asterisk Device-State Sync

## Ziel

Presence-Status automatisch aus dem Asterisk-Telefonstatus ableiten:
- Grün → frei (`NOT_INUSE`)
- Rot → im Gespräch (`INUSE`, `RINGING`, `BUSY`)
- Grau → offline (`UNAVAILABLE`)
- Manuell gesetzter Status (z.B. "Meeting") hat Vorrang bis Gespräch endet

---

## Architektur

```
Asterisk ARI WebSocket
    └─► Backend (FastAPI) – ARI Event Consumer
            └─► DeviceStateChanged → Presence-Update in DB
                    └─► SSE / WebSocket → Frontend Presence-Dashboard
```

---

## Aufgaben

### 1. ARI-Passwort in Umgebungsvariable

`ari.conf` enthält aktuell Plaintext-Credentials (daher in `.gitignore`).

- `docker-compose.yml`: `ARI_PASSWORD` als Env-Var
- `ari.conf`: `password = ${ARI_PASSWORD}` (Asterisk unterstützt Env-Vars in Configs)

### 2. ARI WebSocket Consumer im Backend

Neue Datei: `backend/app/services/asterisk_ari.py`

- Verbindung zu `ws://kitmunicator_asterisk:8088/ari/events?api_key=ari_user:${ARI_PASSWORD}&app=kitmunicator`
- Reconnect-Logik (exponential backoff)
- Event-Filter: `DeviceStateChanged`

```python
# Mapping Asterisk → Presence
DEVICE_STATE_MAP = {
    "NOT_INUSE":   "available",
    "INUSE":       "busy",
    "RINGING":     "busy",
    "BUSY":        "busy",
    "UNAVAILABLE": "offline",
    "INVALID":     "offline",
}
```

### 3. Username-Lookup: Device-Name → User

Asterisk feuert Events auf `PJSIP/jessica` oder `PJSIP/joshua`.
Backend braucht Mapping `SIP-Username → User-ID` (aus DB oder Config).

### 4. Presence-Update-Logik

- Wenn Asterisk `INUSE` meldet → Presence auf `busy` setzen, vorherigen Status merken
- Wenn Asterisk `NOT_INUSE` meldet → auf gemerkten Status zurücksetzen (oder `available`)
- Manuell gesetzter Status (`meeting`, `away`, ...) wird **nicht** durch Asterisk überschrieben — nur der Telefon-Substatus ändert sich

### 5. ARI App registrieren

In `ari.conf` ist nur `enabled = yes` nötig. Die App `kitmunicator` wird beim
WebSocket-Connect automatisch registriert.

### 6. Frontend

Presence-Badge: zusätzliches Telefon-Icon wenn `RINGING`/`INUSE` — unabhängig
vom manuellen Status sichtbar.
